# Clicksend 1.2 Architecture Proposal

Synthesis of four tracks run on 2026-10-06 against the frozen 1.1.0 candidate (`7e96b24`):
- A, hardening: `hardening/1.1`
- B, spikes: `spike/1.2-observability-http`, `spike/1.2-api` and `spike/1.2-webhooks`
- C, ecosystem research: `research/ecosystem`

Each track's evidence is in its own `research/*.md` on its branch. This document only cites it.
No live ClickSend calls were made by any track.

**1.1.0 remains frozen and release-ready.** Track A found no release blocker (details in section 8).

The invariant every item below is judged against: *a send that may have been processed is never
repeated automatically, and surfaces as `Clicksend::AmbiguousRequestError`*, including when a
framework retries a job.

## 1. Keep (already correct)

| Item | Evidence |
|---|---|
| The retry safety rule in `Connection`, not configurable | Track A: 50 new mutants (48 killed, 1 equivalent, 1 unpinned design choice), about 20 hostile transport outcomes and 40×25 concurrent mixed failures, with every send arriving once and every possibly-processed failure ambiguous |
| `AmbiguousRequestError` as an extended module, keeping error classes | A: Marshal keeps the mark and `RequestInfo`. C: Rails' `discard_on`/`rescue_from` accept modules |
| Instrumenter duck-typed to `ActiveSupport::Notifications` | C: Rails 8.1 `Rails.event` bridge in 10 lines. B1: the OTel adapter needs no core change |
| `Response#request` outside the `Data` members | Equality and pattern matching are as in 1.0 |
| FakeAPI is a transport, so the production code paths run; no built-in history | B6 reinforced the decision: history stays stubbed by the test author |
| Webhook parsers over decoded params | B5: every published shape (archived, n8n JSON, Power Automate, documented test pushes) parses with the 1.1 code |
| No global configuration | C: Stripe is moving users from globals to `StripeClient` instances |
| Faraday 2 as the only runtime dependency | Everything proposed below keeps it |

## 4. Reject (would make the gem worse)

| Idea | Why |
|---|---|
| "Not in history ⇒ resend", or a found / not-found-yet result object | ClickSend can't tell "not yet" from "never" (B6) |
| `sms.quote` now | No documentation says `POST /v3/sms/price` is free of side effects, and the example returns a `message_id` (B4). Revisit only with evidence |
| Wrapping `cancel-all` | An empty body cancels every scheduled message; the `custom_string` filter's semantics are undocumented (B3) |
| Webhook HMAC or signature verification | Nothing to verify (B5) |
| Webhook IP allowlist helper | The only list is archived, about 2019, and not republished (B5) |
| A webhook deduplicator with storage in the gem | Persistence coupling; a README recipe suffices (B5) |
| A separate error base class for `Webhook::InvalidPayload` | Breaks "every error is a `Clicksend::Error`"; `discard_on` handles jobs (B5) |
| Persistent connections or httpx as the default | Three extra runtime gems and new false-ambiguity modes (B2). httpx's Faraday adapter enables PUT retries (B2) |
| `clicksend-sidekiq` | `sidekiq_retry_in` returning `:kill`/`:discard` already covers it (C) |
| `clicksend-rspec` as a gem | Opt-in files in core suffice (C) |
| A global `Clicksend.configure`, an ActionMailer-style layer, a Noticed gem, monkey-patching | Coupling without value (C) |
| A gem-owned in-flight ledger table | The marker belongs on the app's own row (C, measured) |
| Managing automation rules; voice, fax and email models | Out of scope for an SMS-focused client (B5) |

## 5. Core vs optional gems

- **Core `clicksend` 1.2:**
  - `sms.cancel`, `sms.search_history`
  - testing helpers, `stub_history`, `fail_next(:interrupted)`
  - the changes in section 2
  - documentation
  - Runtime dependencies stay at Faraday 2 only.
- **`clicksend-opentelemetry`:** a separate gem, own gemspec (`opentelemetry-api`), own CI job, versioned independently.
- **`clicksend-rails`:** 1.3 at the earliest and only on demand. The ActiveJob concern
  (`around_perform` that rescues ambiguity whatever the declaration order, plus a boot-time
  timeout-budget warning), `config.clicksend` and credentials wiring, a Rails logger and
  notifications by default, and test setup. No engine, routes, migrations, ledger table or mailer
  layer. The concern ships first as a README snippet in 1.2.

## 8. Track A result (1.1 hardening)

No A-level finding. One B: the instrumenter lifecycle (a deferred or cross-thread block; it
requires an instrumenter that breaks the documented "yield once, synchronously" contract and
fails on every call, including GETs). C items: C1–C9. D items as listed in the hardening report.
`hardening/1.1` adds 23 specs that pin existing correct behaviour.

## 9. Proposed docs-only corrections to 1.1 (not applied; `next/1.1` is frozen)

1. README: `adapter: [:net_http_persistent, {pool_size: 5}]` is unsafe advice. Make `pool_size` at
   least the number of threads sharing the client, require minimum adapter versions, and warn
   that `with` per request builds a new pool (B2).
2. API notes row "Webhook authentication": "no … IP ranges in any current, archived or help
   source" is wrong. Archived help listed six IPs (about 2019) and advised a URL token. Reword to
   "none current; archived IP list, not republished" (B5).
3. Receipt deduplication: "idempotently by `message_id`" can drop a final receipt, because
   pending 200/300 receipts can be followed by a final one (inferred from help 42318). Key on
   `message_id` plus `status_code`, with final statuses winning (B5).
4. Observability: the stock OpenTelemetry Faraday instrumentation records `url.full`, including
   `q=to:+…`, from `sms.history`. Warn in the README (B1, C).
5. Jobs: `Timeout.timeout { deliver }` raises a plain `Timeout::Error` after the request may have
   arrived. Never wrap sends in `Timeout.timeout`; use the client's timeouts (A: C4).
6. History: "one search filter per request" should say that ClickSend documents a single
   `q=field:value` for history. Its general search docs describe several fields with
   `operator`, but not for this endpoint (B6).
